### [OpenAI Examines Perplexity as a Measure of Model Intelligence](https://openai.com/index/perplexity-and-intelligence/) ⭐️ 7.0/10

OpenAI published a post for AI researchers and practitioners examining the relationship between language-model perplexity and intelligence. The supplied item contains no article body, data, or methodology, so the post&\#x27;s specific arguments and any reported quantitative trend cannot be verified from the available material.

hackernews · acossta · Nov 22, 17:06 · [Discussion](https://news.ycombinator.com/item?id=50601525)

**「Background」** Perplexity is a long-standing pretraining metric that measures how surprised a model is by each next token in a sequence: it bottoms out at 1 for a perfect predictor and rises toward the vocabulary size for random guessing. OpenAI&\#x27;s essay, attributed to chief scientist Jakub Pachocki, argues that this familiar loss measure could give developers a shared way to track emerging capabilities rather than relying on bespoke benchmarks. The piece is a conceptual argument from a vendor rather than an independent result.

**「Community Discussion」** Commenters focused on the metric&\#x27;s continued relevance: one supplied a plain-language definition \(perplexity measures next-token surprise, from 1 at perfect prediction to vocabulary size at random guessing\), another argued that prediction and compression rates should naturally track intelligence, and a third said the apparent trend was surprising given the shift to reinforcement learning. A further comment claimed Microsoft is adopting a shared held-out perplexity evaluation and cited a reported MAI-2 Base log-perplexity of 0.819, a claim not confirmed by the supplied source.

### [Google Reportedly Tests Chrome AI Agent in Simulated Internet](https://www.landian.news/archives/128701.html) ⭐️ 7.0/10

A Landian report says Google built an isolated simulated internet, called Mirror Dimension, to test Chrome&\#x27;s AI agent as it opens websites, searches, logs in, adds items to carts, and completes tasks. The environment reportedly contains thousands of simulated sites, with separate isolation for each engineer and more than 1,000 test cases run daily. The tests focus on defenses against prompt injection and other attacks from malicious webpages; the report does not describe a product release or independently verified results.

telegram · zaihuapd · Nov 23, 01:30

**「Background」** Chrome&\#x27;s browser-use agent — which Google calls &quot;auto browse&quot; — works by having a model read pages and then click, type and navigate on the user&\#x27;s behalf, so text on any page can act as instructions to the model. That makes prompt injection from hostile or compromised pages the core risk, and running such an agent against the live web means a mistake could touch real accounts and purchases. Google&\#x27;s security blog describes Mirror Dimension as a synthetic web of thousands of simulated sites modeled on everyday user journeys, built so engineers can evaluate the agent without that exposure.

**「What it means」** Landian&\#x27;s report indicates that prompt-injection resistance, not just task completion, is an explicit test target for Chrome&\#x27;s agent: Google is said to run more than 1,000 daily cases across thousands of simulated sites in isolated per-engineer environments. For organizations considering browser agents, a clean simulation result should not be treated as proof of safety on arbitrary live pages; they should still constrain what the agent can do with credentials, purchases, and account changes.

### [Microsoft: Windows Server 2028 Omits WoW64 by Default, Restorable via FoD](https://www.windowslatest.com/2026/11/23/32-bit-apps-days-are-numbered-as-microsoft-strips-support-bit-by-bit-starting-with-windows-server-2028-but-windows-11-is-safe-for-now/) ⭐️ 7.0/10

Microsoft said at Ignite 2026 that Windows Server 2028 will ship without the WoW64 32-bit compatibility subsystem by default, so 32-bit applications will not run out of the box. The server release is planned for fall 2027 alongside Windows 11 27H2, and administrators can add WoW64 back as a Feature on Demand, typically via PowerShell or DISM on Server Core. Microsoft said the change is intended to reduce attack surface and block 32-bit malware; it is a default-off policy rather than a full removal, and Windows 11 still includes WoW64 with no announced removal plan.

telegram · zaihuapd · Nov 23, 03:03

**「What WoW64 does」** WoW64 is the Windows compatibility layer that lets 64-bit installations run 32-bit applications. It was previously included by default in Windows Server, so legacy 32-bit software did not require a separate compatibility add-on; Windows Server 2028 turns it into an optional component administrators must add explicitly.

**「Planning need for Server 2028」** Administrators who intend to move existing 32-bit line-of-business software onto Windows Server 2028 will need to add the WoW64 on-demand feature during or after installation — typically via PowerShell or DISM on Server Core — because a default image will not run those apps. Since Windows 11 still includes WoW64, validating an app on a desktop build will not reveal the gap; the 32-bit inventory has to be checked against the server image itself before migration.

### [Structured Flailing: A Practical Heuristic for Uncertain Work](https://seangoedecke.com/when-in-doubt-flail-about/) ⭐️ 6.0/10

rss · Sean Goedecke · Nov 23, 00:00

**「Background」** Sean Goedecke argues that when guidance is absent and the right move is unclear, waiting to understand the situation is often worse than acting. His proposed response is deliberate “flailing”: probing an unfamiliar problem rather than trying to fully map it first.

**「Solution」** The method has three parts: try many different things, watch feedback closely, and ruthlessly drop anything that is not getting positive feedback. Trying many probes matters because most plans will be bad, and because a portfolio prevents overinvestment in any one; feedback should come both from more experienced colleagues and from reality, such as latency or user metrics. Goedecke applies this to product work, where most GitHub Models features failed but an integration allowing AI inference to run from a GitHub Actions token proved sticky and seeded “Continuous AI”; to engineering, where he prefers speculative changes over exhaustively studying systems too large and fast-changing to map; and to organizational problems, where senior engineers can test possible remedies and build trust by abandoning failing ones quickly. He acknowledges the reputational risk and says the approach can feel like repeated failure from the inside, especially if organizational feedback is ignored.

**「Takeaway」** The author’s larger point is that effective engineers must tolerate the sensation of flailing and treat it as a prompt to keep probing, provided they remain sensitive to feedback and quick to abandon what is not working.
