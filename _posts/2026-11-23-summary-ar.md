**「نقاش المجتمع」** ناقش المعلّقون تعريف perplexity بوصفها درجة مفاجأة النموذج عند توقع الرمز التالي، وتتراوح نظريًا بين 1 وحجم المفردات، مع تساؤل عن عدم تعريفها في المقال نفسه. ورأى أحدهم أن ارتباطها بالذكاء ليس مفاجئًا لأن معدل التنبؤ أو الضغط على البيانات يعكس جودة النموذج، بينما أبدى آخر دهشته من وضوح اتجاه cross-entropy رغم انتشار التعلم المعزز.

### [مايكروسوفت: Windows Server 2028 لن يدعم تطبيقات 32 بت افتراضيًا](https://www.windowslatest.com/2026/11/23/32-bit-apps-days-are-numbered-as-microsoft-strips-support-bit-by-bit-starting-with-windows-server-2028-but-windows-11-is-safe-for-now/) ⭐️ 7.0/10

أعلنت مايكروسوفت في مؤتمر Ignite 2026 أن Windows Server 2028 لن يتضمن افتراضيًا النظام الفرعي للتوافق WoW64، وبالتالي لن تشغّل النسخة الجديدة تطبيقات 32 بت بمجرد تثبيتها. والخطة أن يصدر النظام في خريف 2027 إلى جانب Windows 11 27H2. ويمكن للمسؤولين إعادة WoW64 عند الحاجة عبر ميزة عند الطلب \(FoD\)، باستخدام PowerShell أو DISM على Server Core. وقالت مايكروسوفت إن الهدف تقليص سطح الهجوم ومنع برمجيات 32 بت الخبيثة، بينما يبقى WoW64 في Windows 11 دون خطة إزالة معلنة.

telegram · zaihuapd · Nov 23, 03:03

**「خلفية」** WoW64 هي طبقة التوافق التي تتيح لأنظمة Windows ذات النواة 64 بت تشغيل التطبيقات المكتوبة لمعمارية 32 بت، ولهذا فإن غيابها من صورة التثبيت الافتراضية يعني أن البرامج القديمة لن تعمل قبل إضافة المكوّن صراحةً. وفي تثبيتات Server Core، حيث لا توجد واجهة رسومية لإدارة الميزات، تمر إعادة إضافة WoW64 عبر أدوات سطر الأوامر مثل PowerShell أو DISM بدلًا من معالج «الميزات على الطلب» التقليدي، وهو ما يجعل التخطيط المسبق جزءًا من نشر الخادم.

**「أثر عملي على مسؤولي الخوادم」** على مسؤولي الأنظمة الذين ما زالوا يشغّلون تطبيقات 32 بت أن يدرجوا خطوة إضافة WoW64 عبر &quot;ميزة عند الطلب&quot; \(FoD\) بأمر PowerShell أو DISM ضمن إعدادات النشر غير المراقَب وصور الخوادم، وإلا فإن هذه التطبيقات لن تعمل مباشرة بعد التثبيت على Windows Server 2028، وخصوصاً في نواة Server Core. ويستحسن حصر الاعتماديات على 32 بت قبل الترحيل، مع العلم أن Windows 11 لا يزال يحتفظ بـ WoW64 ولم تُعلن مايكروسوفت خطة لإزالته منه.
